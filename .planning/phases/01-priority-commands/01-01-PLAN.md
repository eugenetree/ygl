<user_story>
**As an** operator monitoring the scraping pipeline from Telegram,
**I want to** run `/priority_all` and `/priority_active`,
**so that** I can see, ranked, which channels the scraper considers highest-priority — and which of those still have pending work — without opening a database console.
</user_story>

<objective>
Add two read-only Telegram bot commands that surface pre-calculated channel priority rankings:
- `/priority_all` — top 10 channels by `scrapingScore` descending, each showing rank, name, score, and processed/total video counts (BOT-01)
- `/priority_active` — the same list filtered to channels with at least one `videoJobs` record in status `PENDING` (BOT-02)

Both commands share one use case (`GetChannelPriorityRankingsUseCase`) parameterized by filter `all | active` (D-04); each command has its own thin controller. No schema changes, no new packages, no frontend/API changes — this phase only adds files and wires two new controllers into `TelegramBot`.

Purpose: Give operators direct in-Telegram visibility into channel prioritization, the primary operational window into system state.
Output: One new use case (+ its test), two new controllers, and the four edits to `telegram-bot.ts` that register and advertise the commands.
</objective>
